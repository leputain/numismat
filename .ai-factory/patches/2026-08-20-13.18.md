# Successful auth responses failed in Telegram WebView parsing

**Date:** 2026-08-20 13:18
**Files:** `src/finbot/adapters/http/schemas/auth.py`, `tests/unit/test_http_auth.py`, `web/src/api/client.ts`, `web/src/api/client.test.ts`
**Severity:** high

## Problem

After Telegram login and subsequent session checks returned HTTP 200, the Mini App still displayed a generic protocol error. Server telemetry showed that HMAC authentication, cookie creation, and session reads all succeeded.

## Root Cause

The browser adapter assumed every Fetch implementation exposes `Response.body.getReader()`. Some Telegram WebViews expose only buffered response methods, so a valid JSON response failed locally after the server had returned it. Auth expiry also retained Python microsecond precision, while the portable ECMAScript date interchange form uses millisecond precision.

## Solution

The JSON reader retains its streaming bounded path and adds a compatibility fallback to `Response.arrayBuffer()` when no readable stream is exposed. The fallback enforces the existing Content-Length precheck and a post-read 2 MiB bound before strict UTF-8 and JSON decoding.

Auth session expiry now serializes as UTC RFC3339 with exactly three fractional digits and `Z`. OpenAPI field types and authentication semantics are unchanged.

## Prevention

- Feature-detect optional Web APIs used inside Telegram native WebViews.
- Keep both streaming and bounded buffered response paths under the same payload cap.
- Emit browser-facing timestamps in the portable ECMAScript millisecond interchange form.
- When the server records successful requests but the UI reports protocol failure, inspect client-side post-response validation before changing backend authority rules.
