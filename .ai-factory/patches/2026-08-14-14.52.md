# Docker Compose tmpfs parsing fix

## Problem

Starting the local API and recurring runner failed during container creation with Docker reporting `nodev` as an invalid, non-absolute mount path. The ordinary `docker compose config --quiet` validation passed and therefore did not expose the defect.

## Root cause

Several `tmpfs` values used an unquoted YAML flow sequence. Commas inside the intended mount option string were parsed as YAML item separators, turning one mount into four entries such as `/tmp:noexec`, `nosuid`, `nodev`, and `size=16m`.

## Solution

Quoted the complete comma-containing tmpfs scalar for the API, recurring runner, MCP, and production web services. This preserves the existing `noexec`, `nosuid`, `nodev`, size, and web read/write options without changing the container security model.

## Verification

- Parsed the development and production Compose documents as JSON and verified one exact tmpfs entry per affected service.
- Re-ran real container creation on Docker Desktop.
- Confirmed database health, successful migration completion, healthy bot/API containers, and HTTP live/readiness responses.
- No broad test suite was run for this configuration-only fix.

## Prevention

Quote YAML flow-sequence scalars that contain commas, or prefer block-list syntax. A future lightweight Compose gate should inspect the normalized JSON output because syntax-only validation accepts malformed-but-valid mount lists.

## Logging

No application log was added: the defect occurs before the application process starts. Docker container creation and normalized Compose output are the appropriate diagnostic signals.
