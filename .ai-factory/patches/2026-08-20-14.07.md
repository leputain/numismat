# Exact Origin rejected legitimate Telegram WebView writes

**Date:** 2026-08-20 14:07
**Files:** `src/finbot/adapters/http/mutations/request.py`, `src/finbot/adapters/http/routes/auth.py`, `src/finbot/adapters/http/routes/*.py`, `tests/unit/test_http_auth.py`, `tests/unit/test_http_mutations.py`
**Severity:** high

## Problem

Valid owner sessions could read data but intermittently received `403 origin_forbidden` when creating drafts, budgets,
or other protected records. The same Telegram Mini App could start working after a reopen, so the failure appeared
random to the user.

## Root Cause

Protected mutations and logout treated an exact browser `Origin` value as authorization evidence. Native Telegram
WebViews do not expose one portable Origin contract across platforms and launches: the header may be absent or may
identify a Telegram WebView origin. The signed login path already accounted for that behavior, but subsequent writes
still enforced the browser-only assumption.

Exact Origin equality was not an independent security authority: a non-browser client can choose that header. The
actual write authority is the host-only Secure session plus the independent double-submit CSRF cookie/header; mutations
also require a canonical idempotency key and execute the session lock inside the write transaction.

## Solution

Signed login, logout, and protected mutations now handle a single bounded ASCII Origin as optional transport metadata.
Missing and non-canonical WebView values are accepted only when the endpoint's real authorization proof is valid.
Duplicate, empty, oversized, and non-ASCII Origin values still fail closed, and raw values remain excluded from logs.

Manual mutation OpenAPI parameters now describe Origin as optional metadata while keeping CSRF and idempotency headers
required. Regression tests first reproduced both missing and foreign WebView Origin failures, then verified successful
writes/logout and continued CSRF enforcement.

## Prevention

- Do not use browser metadata as authorization evidence unless every supported embedded client has a documented,
  portable contract for it.
- Model signed login authority and session-bound mutation authority separately.
- Keep WebView compatibility tests for absent and foreign Origin metadata on both logout and protected mutations.
- Preserve fail-closed structural header validation and never log raw Origin, cookies, CSRF values, or request bodies.
- Keep OpenAPI security requirements aligned with runtime enforcement after changing an admission boundary.
