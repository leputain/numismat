# Browser natives lost their receiver in Telegram WebView

**Date:** 2026-08-20 13:44
**Files:** `web/src/api/client.ts`, `web/src/api/client.test.ts`, `web/src/features/auth/auth-coordinator.ts`, `web/src/features/auth/auth-coordinator.test.ts`
**Severity:** high

## Problem

The Mini App displayed a protocol error even when the production API returned a valid authenticated session or a valid `auth_session_invalid` JSON envelope. The previous compatibility fallback helped only when `Response.body` or `getReader()` was absent, and the successful-session path still failed after JSON parsing.

## Root Cause

The auth coordinator stored native `setTimeout` and `clearTimeout` functions in private fields and invoked them as class methods. That changes the JavaScript receiver from `Window` to `AuthCoordinator`; WebKit enforces the native receiver and throws, while Chromium tolerates it. The exception occurred immediately after a valid session was parsed and was converted to `protocol_error`.

Some Telegram WebViews also expose the Web Streams surface without a reliably usable reader. A present `Response.body.getReader()` could throw before the buffered fallback was selected. Direct stream cancellation had the same method-presence assumption.

## Solution

Native time and timer dependencies are now wrapped in plain closures. Default timers are invoked through `globalThis`, preserving the required browser receiver; injected test adapters are invoked as ordinary functions.

Small same-origin JSON responses now use the oldest interoperable Fetch body method, `Response.text()`. The reader keeps the Content-Length precheck and enforces the same 2 MiB limit again on the decoded UTF-8 byte length before parsing JSON. Response disposal now feature-detects `cancel()` instead of calling it merely because a body object exists.

One regression emulates WebKit's receiver enforcement and proves that a successful session reaches `authenticated`. Another models a WebView with a declared but throwing `getReader()` and proves that a valid 401 envelope reaches the typed HTTP error path.

## Prevention

- Do not treat optional Web API method presence as proof of a working implementation in embedded WebViews.
- Do not detach native browser functions unless they are explicitly bound or invoked through a receiver-preserving wrapper.
- Prefer stable Fetch Body mixins for small, server-bounded same-origin payloads.
- Reproduce compatibility failures with partially implemented APIs, not only missing APIs.
- Keep payload bounds independent of the selected browser body-reading mechanism.
