# Transient Mini App failures became an unrecoverable screen

**Date:** 2026-08-24 17:57
**Files:** `web/src/app/error-boundary.tsx`, `web/src/app/routes.tsx`, `web/src/app/shell/app-shell.tsx`, `web/src/adapters/telegram/telegram-web-app.ts`, related tests
**Severity:** high

## Problem

The Telegram Mini App displayed a global "interface unavailable" screen even though the edge,
API, database, and background containers remained healthy. Closing and reopening the Mini App
could display the same screen again.

## Root Cause

The exact first JavaScript exception was intentionally unavailable because production client
diagnostics do not retain error details or user data. The persistent failure itself was
deterministic: the global React error boundary permanently latched after one exception, unmounted
the authentication and application providers, and exposed no recovery action. Telegram Desktop
may reuse the same WebView after close/reopen, so the boundary remained latched.

The release had also moved every application page behind a dynamic route import, including the
capture, transaction list, and transaction detail path. That made the primary save-and-review
journey vulnerable to a late route chunk failure during or after a deployment. Separately, two
Telegram SDK version reads could throw synchronously before the authentication coordinator had a
chance to convert the failure into a safe auth state.

## Solution

- The fatal boundary now classifies known dynamic-import failures without retaining details and
  provides an explicit page reload action. The fallback states that mutations are not repeated
  automatically.
- Dashboard, draft, transaction list, and transaction detail pages are bundled with the entry
  graph. Secondary heavy pages remain lazy-loaded.
- Optional Telegram SDK version checks and SDK shape validation are fail-closed inside the adapter;
  native getter failures no longer escape into React, and an already-bound back listener is still
  removed if a later capability check fails.
- Route scroll synchronization uses the broadly compatible numeric call and contains native WebView
  failures instead of escalating them into the global boundary.
- Regression tests first reproduced the dead-end chunk fallback and the unguarded SDK getter, then
  verified the recovery UI and contained adapter behavior.

## Prevention

- Keep core mutation-to-review navigation independent from deploy-time lazy chunks unless the edge
  retains previous hashed assets for at least one rollout window.
- Every global UI boundary must provide a recovery action that does not retry financial writes.
- Treat every Telegram SDK property, including capability and version getters, as untrusted native
  integration state.
- Preserve privacy-safe production diagnostics; correlate exact future incidents with fixed error
  classes rather than raw exception messages or payloads.
